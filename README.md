# Information:
6th semester game project for summer semester 2025 in the "Animation & Game" study course from the Darmstadt University of Applied Sciences "Hochschule Darmstadt" (h_da). This GitHub repository is there to display as part of my portfolio.

# Summary
In the top down action game "Fungus Takeover" , you fight against surviving life forms in a post-human, nuclear wasteland. As the parasitic mushroom "Fungus Mortis Vomens" you infect defeated enemies, reanimate them with your spores and turn them into loyal units which help grow and spread your fungal network.

# How to view
To view the project use the Unity Editor (Version: 6000.0.59f2).

# How to play
Download the Build available on itch.io and open the executable to play the game.

# Skills learned
- Structure Programming for Feature Programmers to utilize, making it easier to create new features and fill in dependencies where needed through decoupling.
- Utilized Controller-Model-View Structure for Gameobjects
- Modular Configuration File (Scriptable Objects) for various different Entities, that can be swapped out for Playtesting or Creation of Variants
- Instantiating through Extenject Dependency Injection (https://github.com/Mathijs-Bakker/Extenject) 
- Cleaned up Inspector with OdinInspector (https://odininspector.com) and Enum Flags for Game Designers to easily and effectively change values of objects 
- UX Design Iterrations and PlayerTesting
- Procedural Generation, unused cause the progress of the game has met unforeen delays. Originally, the game would include dungeon rooms, so I tested out Procedural Generationin Preproduction
- Settings for Music & Sounds
- Controller Keys Rebinding Settings for Unity's Input System

# Challenges
Structures were too overengineered for a 3-4 month project, needing more time to explain and introduce to the Feature Programmer. However Time was scarce this semester especially due to the sheer amount of incidents this semester affecting all team-member, making back & forth dependency handling and bug fixing difficult.
For the same reason, it was difficult for me to try and actually implement more new stuff, cause I was constantly demanded to take care that the Feature programmer and other departments have their needs fulfilled. I took a look into Automation of Script Creation and Analyzing through Roslyn in vain.
